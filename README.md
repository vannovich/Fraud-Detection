# 🛡️ Fraud Detection System

An end-to-end machine learning project that detects fraudulent financial transactions. It covers exploratory data analysis, a scikit-learn model pipeline, and a Streamlit web app for real-time predictions.

## 📌 Overview

Fraud is rare but costly. In this dataset, only a tiny fraction of transactions are fraudulent, which makes plain accuracy a misleading metric. This project explores how fraud behaves across transaction types and amounts, trains a classifier that handles the heavy class imbalance, and serves the model through a simple web interface.

**Highlights**

- In-depth EDA on transaction types, amounts, balances, and time steps
- Class-imbalance handling with stratified splitting and balanced class weights
- A single scikit-learn `Pipeline` (scaling + encoding + model) so training and prediction preprocessing always match
- An interactive Streamlit app to test transactions and see the fraud prediction and probability

## 📊 Dataset

The data is a Kaggle transaction dataset in the style of the PaySim mobile-money simulator.

- **Source:** [Fraud Detection Dataset on Kaggle](https://www.kaggle.com/datasets/amanalisiddiqui/fraud-detection-dataset)
- **Target:** `isFraud` (1 = fraudulent, 0 = legitimate)

| Column | Description |
|---|---|
| `step` | Time unit of the simulation (1 step = 1 hour) |
| `type` | `CASH_IN`, `CASH_OUT`, `PAYMENT`, `TRANSFER`, or `DEBIT` |
| `amount` | Transaction amount |
| `nameOrig` / `nameDest` | Sender and receiver identifiers |
| `oldbalanceOrg` / `newbalanceOrig` | Sender balance before and after the transaction |
| `oldbalanceDest` / `newbalanceDest` | Receiver balance before and after the transaction |
| `isFraud` | Ground-truth fraud label |
| `isFlaggedFraud` | Rule-based system flag (dropped from modelling) |

The dataset is large, so it is not committed to this repository. Download it from Kaggle and place the CSV in the `data/` folder.

## 🔍 Exploratory Data Analysis

Key questions explored in the notebook:

- **Class imbalance:** what percentage of transactions are fraud?
- **Fraud by transaction type:** which types carry the highest fraud rate? Fraud concentrates in `TRANSFER` and `CASH_OUT`.
- **Amount distribution:** amounts are heavily right-skewed, so a `log1p` transform reveals a clear bimodal shape.
- **Amount vs. fraud:** box plots comparing legitimate and fraudulent transactions.
- **Balance behaviour:** sender balances that drop to zero after a `TRANSFER` or `CASH_OUT`, and negative balance differences.
- **Fraud over time:** fraud counts per time step.
- **Repeat senders and receivers:** top accounts by transaction volume and fraud.
- **Correlations:** a heatmap of numeric features against `isFraud`.

## 🧠 Modelling Approach

1. **Feature selection:** dropped identifiers (`nameOrig`, `nameDest`), the rule-based `isFlaggedFraud`, and `step`.
2. **Train/test split:** 70/30, stratified on `isFraud` to preserve the fraud ratio.
3. **Preprocessing** (inside a `ColumnTransformer`):
   - `StandardScaler` on the numeric features
   - `OneHotEncoder(drop="first")` on `type`
4. **Model:** `LogisticRegression(class_weight="balanced", max_iter=1000)`
5. **Evaluation:** classification report and confusion matrix, with focus on fraud-class precision and recall rather than accuracy.
6. **Export:** the full pipeline is saved with `joblib` as `fraud_detection_model.pkl`.

## 🚀 Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/<your-username>/<your-repo>.git
cd <your-repo>
```

### 2. Create a virtual environment and install dependencies

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Add the dataset

Download the CSV from Kaggle and place it at `data/AIML Dataset.csv`.

### 4. Train the model (optional)

Open `analysis_model.ipynb` and run all cells. This regenerates `fraud_detection_model.pkl`.

### 5. Launch the app

```bash
streamlit run app.py
```

The app opens at `http://localhost:8501`.

## 🖥️ Using the App

1. Choose the **transaction type**.
2. Enter the **amount** and the **sender and receiver balances** (before and after).
3. Click **Predict**.
4. The app shows whether the transaction is flagged as fraudulent, along with the fraud probability.

## ⚠️ Limitations

- The dataset is simulated, so performance may not transfer directly to real-world transaction data.
- The model uses post-transaction balances (`newbalanceOrig`, `newbalanceDest`), which may not be available at decision time in a live system.
- With such rare fraud, the decision threshold should be tuned to balance missed fraud against false alarms.
- This project is for learning and demonstration and is not production-ready.
